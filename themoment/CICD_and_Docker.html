2026.09.22

CI/CD와 Docker에 대해 알아보자.

github CI/CD workflows

github의 CI/CD는 .yml 형식으로 적성된다.

readygsm 배포코드를 통해 자세히 알아보자.

트리거

on:
  push:
    branches:
      - master

위 코드처럼 언제 배포할지 설정할 수 있다.

가상 환경

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

위와 같이 어느 가상 환경에서 코드를 실행할지 설정할 수 있다.

코드 가져오기

    steps:
      - name: Checkout
        uses: actions/checkout@v4

위와 같이 repo 코드를 가상 환경에 가져온다. actions/checkout@v4는 사전에 이미 마켓플레이스에 올라온 액션이다.

환경 구축

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up JDK 21
        uses: actions/setup-java@v4
        with:
          java-version: "21"
          distribution: "temurin"

위와 같이 Java등의 환경을 구축할 수 있다. actions/setup-java@v4는 사전에 이미 마켓플레이스에 올라온 액션이다. 

      - name: Build JAR
        run: ./gradlew bootJar -x test --no-daemon

run를 통해 cli 명령을 실행할 수도 있다.

배포

      - name: Deploy to EC2 via SSM
        env:
          INSTANCE_ID: ${{ steps.infra.outputs.instance_id }}
          PROD_ECR_IMAGE: ${{ steps.build-image.outputs.image_uri }}
          ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
          AWS_REGION: ${{ env.AWS_REGION }}
          APP_DOMAIN: ${{ secrets.APP_DOMAIN }}
        run: |
          set -e
	  ...

최종적으로 클라우드 서버에 배포하는 코드이다. secrets.APP_DOMAIN을 보면 알 수 있듯, 비밀키등을 외부에서 가져올 수 있다. github의 Vault라는 가상 저장소에 저장되는 값이라고 한다.

Docker in ReadyGSM

Stage

develop branch에 push가 발생하면 배포가 시작된다. github actions가 stage용 vm에 빌드한 프로젝트 jar파일과 compose용 docker파일, nginx 설정 파일을 전송한다.

서버가 파일을 받은 후에는 docker compose를 통해 환경을 구성한다. nginx, certbot, 실제 서비스 앱, mysql, redis등을 실행한다.

Prod

master branch에 push가 발생하면 배포가 시작된다.

  1. github actions가 jar파일을 빌드한다.
  2. pulumi를 통해 aws 환경을 구축한다.
  3. 도커 이미지를 빌드한다.
  4. AWS ECR에 이미지를 올린다.
  5. AWS EC2에 배포 명령을 보낸다.
  6. AWS EC2에서 docker compose를 실행한다.

최초로 docker compose하면 nginx, certbot, 실제 서비스 앱, mysql, redis등을 실행한다. 이후에는 app 컨테이너만 새 이미지로 교체한다. mysql이나 redis는 유지된다.
