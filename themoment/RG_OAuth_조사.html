RG OAuth 조사

2026.09.03

OAuth의 진행 흐름과, ReadyGSM에서의 OAuth 흐름을 알아보자.

OAuth

클라이언트가 서버에 로그인 요청을 보내면 서버가 OAuth 서버에 다음과 같은 것들을 넘겨준다:

  • Client ID - 클라이언트가 로그인을 시도하는 유저를 말하는게 아니라, OAuth 서비스를 이용중인 서버를 말한다.
  • Redirect URI - 로그인 완료 후에 돌아갈 주소이다.
  • Response Type - 인증 후 토큰 줄지, 코드 줄지 등등 설정
  • Scope - 어느 범위의 권한을 원하는지 보냄

그 후 클라이언트를 OAuth용 로그인 페이지로 rediect 시킨다. 로그인을 성공적으로 마친다면 토큰이나 코드와 함께 Redirect URI로 다시 redirect 된다.

그리고 Redirect URI에서 클라이언트가 가진 토큰/코드를 Client ID와 Client Secret과 함께 OAuth 서버에 보낸다. 올바른 요청을 보냈다면 서버가 Access Token을 얻게 되고 그걸로 사용자 계정 API를 쓰든 말든 하면 된다.

OAuth in RG

RG에서는 프론트가 Authorization Code를 얻어서 백엔드로 전달해준다. 그 후에 백엔드는 해당 코드로 Access Token을 얻는 구조인듯 하다.

명시적으로 오류 상황에 응답하는 코드를 작성하지 않고 오류만 발생시키는 듯. Error Handler가 잡아서 응답으로 처리해주는 듯 하다.

DataGSM 전용이 아니라 외부에서 Provider를 받아서 처리하는 듯 하다. 현재 지원하는 Provider는 Kakao와 Google.

아직 외부에서 의존성을 주입하는 구조가 마음에 들지 않는 것 같다.. 빨리 익숙해져야지.
