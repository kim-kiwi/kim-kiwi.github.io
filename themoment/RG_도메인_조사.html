RG 도메인 조사

2026.09.15

activity, application, auth, user가 요청을 처리하는 흐름을 알아보자.

Controller는 요청을 받고 Service를 호출한다. Service는 데이터를 검증하고 Repository로 DB를 조회하거나 변경한 뒤 DTO를 반환한다.

인증 정보는 Spring Security Session에 저장된다. 활동 조회와 로그인은 공개 API이고, 신청과 내 정보 조회는 로그인이 필요하다. /admin API는 ADMIN 이상의 권한이 필요하다.

activity

  • GET /api/v1/activity - 모든 활동과 활동별 전체 신청 인원을 조회한다.
  • GET /api/v1/activity/{id} - 활동 하나와 신청 인원을 조회한다. 활동이 없으면 404가 발생한다.
  • POST /api/v1/activity/admin - 활동 정보와 신청 기간을 검증한 후 새 활동을 저장한다.
  • PATCH /api/v1/activity/admin/{id} - 기존 활동 정보를 변경한다.
  • DELETE /api/v1/activity/admin/{id} - 활동을 삭제한다.

생성, 수정, 삭제는 ADMIN용 API다. 신청 시작은 종료보다 빨라야 하고, 신청 마감은 실제 활동 시작보다 빨라야 한다.

application

활동 신청

POST /api/v1/application/apply?activityId={activityId}

동시 신청에도 정원을 정확히 계산하도록 활동을 비관적 쓰기 잠금으로 조회한다.

USER는 신청 기간과 전화번호 중복을 검사한다. 권한과 관계없이 한 사용자는 전체 활동 중 하나만 신청할 수 있다.

정원이 차면 예비 신청자가 되며 예비는 최대 3명이다. 저장 후 본신청 여부와 예비 순번을 반환하고 Discord 알림을 보낸다.

신청 취소와 조회

  • DELETE /api/v1/application/cancel?activityId={activityId} - 신청 기간 안에서 자신의 신청을 취소한다.
  • GET /api/v1/application/my - 자신의 신청 정보와 예비 순번을 조회한다.

본신청자가 취소하면 가장 먼저 등록한 예비 신청자가 본신청자로 올라간다.

관리자 API

  • GET /api/v1/application/admin/applications?activityId={activityId} - 활동별 신청자와 예비 순번을 조회한다.
  • DELETE /api/v1/application/admin/cancel/{id} - 특정 신청을 삭제하고 필요하면 예비 신청자를 올린다.
  • GET /api/v1/application/admin/excel?activityId={activityId} - 본신청자와 예비 신청자를 Sheet로 나눈 Excel 파일을 내려받는다.

auth

OAuth 로그인

POST /api/v1/auth/{provider}

Google과 Kakao를 지원한다. 프론트가 Authorization Code와 redirect URI를 넘기면 백엔드가 Access Token과 사용자 이메일을 가져온다.

가입한 적이 없다면 USER 계정을 만든다. 그 후 Spring Security 인증 정보를 새 Session에 저장한다.

로그아웃

POST /api/v1/auth/logout

현재 Session과 Spring Security 인증 정보를 지운다.

user

  • GET /api/v1/user/me - Session의 id, 이메일, 권한을 반환한다. DB는 다시 조회하지 않는다.
  • PATCH /api/v1/utility/user/role - 개발 환경에서 이메일로 사용자의 권한을 변경한다. 운영 환경에는 생성되지 않는다.
